# AX and Paperclip evaluation (2026-10-01)

Verdict: borrow AX's declarative launch/condition patterns; borrow Paperclip's atomic checkout, diagnosis deduplication and native-runtime continuity checks. Paperclip is also a credible candidate for a task/governance backend, pending an isolated integration proof. Neither is adopted as the live orchestrator. The existing native interactive sessions, Telegram relay, role identities, publication authority and subscription scheduler remain requirements.

## Revisions and scope

- AX: commit [ac2332829f22360ff97b0ba34d94dd0dd782f17e](https://github.com/google/ax/tree/ac2332829f22360ff97b0ba34d94dd0dd782f17e), Apache-2.0.
- Paperclip: commit [f48bbba2badd23161abe6a82c81d7a1ea038a4e5](https://github.com/paperclipai/paperclip/tree/f48bbba2badd23161abe6a82c81d7a1ea038a4e5), MIT.
- Both public repositories were checked out into temporary evaluation directories. Findings below come from tracing source and inspecting selected upstream tests, not just the Radar summaries. No dependency install, upstream test execution, provider/model call, credential probe, daemon restart or live configuration change was performed. Go and pnpm are not available in this environment. This is a source-fit assessment, not a runtime validation or comprehensive security audit.
- Any future code reuse must retain the appropriate license notices and pin reviewed revisions. Product descriptions and roadmap entries are not evidence of enforced controls.

## Useful features and design decisions

| Project / mechanism | Source evidence | Decision for our design |
|---|---|---|
| AX: strict versioned manifests | `pkg/apis/v1alpha1/types.go:45–81` bridges YAML through strict protobuf decoding; `ax.proto` separates task, workspace and model specifications | A protected launch manifest resolves worktree identity, runtime versions, instructions/skills/MCP references, permissions and resource profile. Reject unknown fields and unsupported controls. Record the admitted digest; do not replace interactive sessions with cluster jobs. |
| AX: conditions and inspectable lifecycle | `internal/controller/reconciler.go` records readiness reasons; `runner/runner.go` separates metadata service lifetime from child-command exit | Distinguish requested state, observed process state, workspace readiness and task completion. Verify prerequisites before executing a turn. Keep recoverable state inspectable after failure. |
| Paperclip: atomic task checkout and dependency gates | `server/src/services/issues.ts:11375–11585` checks blockers, then conditionally updates expected status, assignee and execution/check-out run IDs | Atomically claim each work item's execution under the existing root task. Distinguish accountable ownership from an active execution lease; same-run replay is idempotent. Fence stale broker operations and prove the old writer stopped before transferring a worktree. |
| Paperclip: material-state watchdog fingerprints | `server/src/services/task-watchdogs.ts:305–545,1622–1664` suppresses reviewed stopped snapshots and revalidates scope before mutation | Strengthen the existing three-handoff watchdog, without adding an always-running agent: persist a diagnosis fingerprint, coalesce unchanged findings and reject stale diagnostic actions. Include verified evidence/milestone revisions in our fingerprint. |
| Paperclip: native checkpoint compatibility | `server/src/services/native-runtime/native-session-resume.ts:20–80,383–558` binds checkpoints to tool contract, provider, task, agent and workspace | Check runtime/tool/permission compatibility and independently verify the exact provider session before using a compact resume delta. On mismatch preserve the original and use the existing support-repair/verified-handoff path, not silent replacement. |
| Paperclip: Codex turn controls and reconciliation | `packages/paperclip-runner/src/drivers/codex/codex-harness-session.ts:315–342,653–765` validates thread/turn identity and passes `expectedTurnId` to steering | Pin and negotiate adapter capabilities; guard steer/interrupt and reconcile the recorded active turn. Unsupported capabilities must be visible, not converted to a different interaction mode silently. |
| Paperclip: bounded provider quota observations | `server/src/services/quota-windows.ts` isolates provider failures; both local adapters return usage windows and sources | Borrow the typed observation/failure contract, not its account-selection or spending policy. Privileged read-only probes feed our one provider/account admission scheduler, including in-flight reservations and the 10% owner reserve. |

## AX: useful patterns, not a drop-in runtime

The current deployment requires Kubernetes, Agent Substrate and Redis, and upstream warns that core specifications are pre-stable. For this single-PC setup, protected local manifests, role UIDs and systemd/cgroup supervision can deliver the useful capabilities without adopting that cluster control plane. [Pinned README](https://github.com/google/ax/blob/ac2332829f22360ff97b0ba34d94dd0dd782f17e/README.md#L65).

Important implementation limits:

- CPU/RAM requests and limits exist in `TaskSpec.resources`, but searches of the Go sources found their uses only in generated schema code and a serialization test. The current template construction accepts image/environment/command, not task resources. This does not establish enforcement of per-task requested limits; underlying Substrate defaults may still apply. Our resource profile needs actual target-runtime enforcement and tests, including detached descendants. [Schema](https://github.com/google/ax/blob/ac2332829f22360ff97b0ba34d94dd0dd782f17e/pkg/apis/v1alpha1/ax.proto), [template construction](https://github.com/google/ax/blob/ac2332829f22360ff97b0ba34d94dd0dd782f17e/internal/substrate/client.go#L213).
- Failed repository setup returns a result with a nil error, withholding only its marker. The runner decides readiness from errors alone, so that path can report ready. It also launches the task command after setup errors. These source paths are a concrete reason to require verified readiness and fail-closed execution in our launcher; they were not reproduced in a running AX deployment. [Workspace setup](https://github.com/google/ax/blob/ac2332829f22360ff97b0ba34d94dd0dd782f17e/internal/workspace/setup.go#L82), [runner](https://github.com/google/ax/blob/ac2332829f22360ff97b0ba34d94dd0dd782f17e/runner/runner.go#L110).
- Custom-template creation failure falls back to the default template. Suspend failure is logged, but the task is still recorded as suspended. Neither behavior is suitable for our identity/permission and desired-versus-observed state guarantees. [Reconciler](https://github.com/google/ax/blob/ac2332829f22360ff97b0ba34d94dd0dd782f17e/internal/controller/reconciler.go#L170).
- The actor template snapshots workspace data, not a live CLI process. Workspace initialization uses forced checkout; rerunning it against recovered dirty work is not our handoff/recovery mechanism. Preserve and reconcile dirty state instead. [Snapshot configuration](https://github.com/google/ax/blob/ac2332829f22360ff97b0ba34d94dd0dd782f17e/internal/substrate/client.go#L262), [checkout](https://github.com/google/ax/blob/ac2332829f22360ff97b0ba34d94dd0dd782f17e/internal/workspace/setup.go#L231).
- Workload identities, least-privilege setup/runtime policy, and budget/approval governance appear in the roadmap. The pinned API has Task, Workspace and Model, not the Gateway primitive described by the supplied Radar page. Do not credit roadmap security features as deployed boundaries. [Roadmap](https://github.com/google/ax/blob/ac2332829f22360ff97b0ba34d94dd0dd782f17e/docs/roadmap.md), [current kinds](https://github.com/google/ax/blob/ac2332829f22360ff97b0ba34d94dd0dd782f17e/pkg/apis/v1alpha1/types.go#L33).

## Paperclip: stronger reuse candidate, with policy mismatches

Correction to the earlier adapter-only assessment: Paperclip is not limited to ACP/headless invocations. This checkout includes a native runner and a Codex app-server driver, with exact thread identity, active-turn reconciliation and guarded steering. Its default transport still starts its own app-server over stdio; this inspection does not demonstrate attachment to our existing remote-control daemon or preservation of the same phone/app session under separate role UIDs. The legacy/local adapters and native runtime must be assessed separately. [Driver contract](https://github.com/paperclipai/paperclip/blob/f48bbba2badd23161abe6a82c81d7a1ea038a4e5/packages/paperclip-runner/docs/codex-driver.md), [transport spawn](https://github.com/paperclipai/paperclip/blob/f48bbba2badd23161abe6a82c81d7a1ea038a4e5/packages/paperclip-runner/src/drivers/codex/app-server-transport.ts#L435).

Policy mismatches to resolve before integration:

- `local_trusted` assigns unauthenticated requests a board administrator identity. A worker able to reach that server could omit its agent bearer token; loopback alone does not distinguish roles. Use authenticated deployment and a protected broker/owner interface with no ambient worker board access. This is a mismatch with our prompt-injection threat model, not a claim that upstream's explicitly trusted mode is an authentication bypass in authenticated mode. [Actor middleware](https://github.com/paperclipai/paperclip/blob/f48bbba2badd23161abe6a82c81d7a1ea038a4e5/server/src/middleware/auth.ts#L228).
- Budget admission compares recorded `billed_cents` at company/agent/project scope. Subscription window observations are a different subsystem. Neither proves a 10% owner reserve with concurrency/in-flight reservations, or prevents a fresh task chain resetting our task-wide limits. Preserve our single scheduler and root ledger. [Budget admission](https://github.com/paperclipai/paperclip/blob/f48bbba2badd23161abe6a82c81d7a1ea038a4e5/server/src/services/budgets.ts#L745), [quota aggregation](https://github.com/paperclipai/paperclip/blob/f48bbba2badd23161abe6a82c81d7a1ea038a4e5/server/src/services/quota-windows.ts).
- Codex quota polling tries app-server RPC, then local credentials and ChatGPT's backend usage endpoint; Claude tries OAuth usage and CLI fallbacks. These are valuable adapter references, not proof of a stable supported endpoint or correct account selection for our role-isolated setup. Never run stock credential-discovery probes inside workers; pin, verify account provenance and isolate probes from model work. [Codex quota](https://github.com/paperclipai/paperclip/blob/f48bbba2badd23161abe6a82c81d7a1ea038a4e5/packages/adapters/codex-local/src/server/quota.ts#L600), [Claude quota](https://github.com/paperclipai/paperclip/blob/f48bbba2badd23161abe6a82c81d7a1ea038a4e5/packages/adapters/claude-local/src/server/quota.ts#L543).
- Its stopped-state fingerprint excludes comment/document/work-product timestamps. That prevents metadata churn waking reviewers, but our progress detector must additionally include verified evidence revisions so genuinely new proof gets reconsidered. Its task watchdog is not a substitute for active-loop progress checks. [Material fingerprint](https://github.com/paperclipai/paperclip/blob/f48bbba2badd23161abe6a82c81d7a1ea038a4e5/server/src/services/task-watchdogs.ts#L319).
- Native resume incompatibility can create a new normalized session with full context; replacement after resume failure is allowed in some cases, while unfinished durable goals require the same session. Borrow compatibility checks, but retain our stricter pending/repair policy and exact-ID recovery. A terminal DB run also does not alone prove all local writers exited. [Recovery policy](https://github.com/paperclipai/paperclip/blob/f48bbba2badd23161abe6a82c81d7a1ea038a4e5/server/src/services/native-runtime/native-session-resume.ts#L383).
- First-party telemetry is enabled by default outside CI unless disabled through configuration or opt-out environment variables. Any prototype must disable it before first launch and audit other egress, credential staging and subprocess paths. [Telemetry configuration](https://github.com/paperclipai/paperclip/blob/f48bbba2badd23161abe6a82c81d7a1ea038a4e5/packages/shared/src/telemetry/config.ts#L65).

A possible future integration uses Paperclip's task/governance UI and storage through a relay adapter, with one authoritative operational ledger and no second session launcher, scheduler, approval path or GitHub publisher. Full consistent component state must join daily backups; company exports are not a substitute. Adoption requires demonstrating native-session continuity, all-source admission, role/owner isolation, root-budget inheritance, crash reconciliation and clean-machine restore, then measuring completed tasks, owner interventions and coordination quota against the relay-only approach. This is a candidate, not an added implementation dependency.

## Validation status and next gates

Inspected upstream tests include AX's workspace Git-error/marker and runner exit/lifetime cases; Paperclip's stale-execution-lock routes, watchdog classifier, quota-provider timeout isolation and native-session-resume tests. They cover meaningful local contracts but were not run here. In particular, AX's Git-error test does not establish end-to-end runner readiness after a clone failure.

The design now requires competing-checkout/fencing tests, failed-bootstrap and failed-suspend tests, detached-child resource accounting, fingerprint deduplication plus new-evidence/stale-diagnosis tests, and runtime/tool-contract drift during exact-ID resume. Existing tool-switch, security, pacing and restore acceptance gates still apply. No productivity or recovery guarantee is inferred solely from passing upstream unit tests.
